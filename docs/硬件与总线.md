# 硬件与总线（ML1.0 实机）

本文件记录真实硬件的**已确认参数**与**尚待确认项**，以及 STM32H723VGT6 的外设分配。
凡是推断出来的数字都标了"推算"，不得当作手册值使用。

## 1. 电机

| 位置 | 型号 | 关键参数 | 来源 |
|---|---|---|---|
| 髋关节 | **灵足 RobStride 01** | 额定负载 **6 N·m**；额定电压 36 VDC；范围 24–48 VDC；空载转速 315 rpm；空载电流 0.5 Arms；绝缘 Class B；工作温度 −20~50 ℃ | `product_manual_robStride01` 第 2 页 §1.2.3、§1.3 |
| 轮 | **上海瓴控 MF9025** | 力矩/电流命令为**原始电流 LSB**；额定电流是设备参数 `0x00B2 motorRatedCurrent`（0.01 A）；每 LSB 电流由 `0x00A4 iScaleCurrentPerLsb` 给出 | `上海瓴控 苏州控越 CAN通信协议 V2.4` |
| 曲柄 | **待确认** | 用户只给了髋与轮两种电机；若曲柄也是 RobStride 01，按下表执行；若是其他型号必须补 | — |

### 两个必须注意的点

1. **灵足 01 的峰值力矩手册这一页没有**。6 N·m 是**额定**负载。控制器现在按额定值限幅（保守），
   若手册另有峰值（通常为额定 2–3 倍）且允许短时使用，可放宽——**但要有书面依据**。
2. **MF9025 命令的是电流，不是转矩**。实际转矩 = Kt × 减速比 × 效率 × 电流，
   这三者都不是协议里的固定常数：减速比在 `0x00BE/0x00BF`，电流比例在 `0x00A4`。
   因此**上电必须读设备参数**，不能把 N·m 写死。

## 2. 控制器实测力矩需求（重要）

在真实限幅（腿 6 N·m、轮 3 N·m）下重跑 SIL 20 s，仍 PASS：

```
worst |pitch| 4.03 deg   final 3.94 deg
peak |tau|  0.66 0.59 0.89 0.66 0.59 0.89   (L hip, L crank, L wheel, R hip, R crank, R wheel)
```

即：**髋/曲柄只用掉额定值的 11%，轮用掉 3 N·m 假设值的 30%**。
这说明之前写成 ±30 N·m 并没有把结果"喂大"——真实需求本来就只有 0.9 N·m 量级。

## 3. CAN 总线（MF9025，已从协议文档确认）

| 项 | 值 |
|---|---|
| 类型 | 经典 CAN 2.0B 数据帧 |
| 波特率 | **1 Mbit/s**（可通过参数 `canBaudRate` 修改，改后需重启生效） |
| 帧格式 | 11 位标准帧（可配扩展帧，两端须一致） |
| 请求 ID | `0x140 + 节点ID` |
| 回复 ID | 默认与请求相同（`differentAckId=0`）；`differentAckId=1` 时为 `0x180 + 节点ID` |
| 节点 ID | 拨码 1–8（`driverId=0` 时）；`driverId=1..63` 时用参数 |
| 0xA1 | 转矩/电流控制 → 回复状态 2 |
| 0x9C / 0x9D | 读状态 2（Iq）/ 三相电流 |
| 0x81 | 以 0 扭矩电流停止 |
| 状态 2 字段 | 母线电流 0.01 A、母线电压 0.01 V、Iq 原始 LSB |

### 灵足 01 的 CAN 协议（手册 §4，第 19 页）

手册是扫描件（72 页的文本层只有 87 字符），协议通过渲染页面读出：

| 项 | 值 |
|---|---|
| 接口 | CAN 2.0，**1 Mbps**，**29 位扩展帧** |
| CAN ID 范围 | 0x01 ~ 0x7F |
| 驱动器供电 | 48 VDC；最大相电流 32 Apk |
| ID 结构 | `bit28..24` = 通信类型；`bit23..8` = 数据区 2；`bit7..0` = 目标电机 CAN_ID |
| 数据类型 0 | 获取设备 ID（应答 data 为 64 位 MCU 唯一 ID） |
| **数据类型 1** | **运控模式**（MIT 风格，5 个参数） |
| 其他模式 | 电流模式（给定 Iq）、速度模式、位置模式 |

**运控模式（类型 1）的帧布局**：

- ID：`bit28..24 = 1`，`bit23..8 = 力矩`（0…65535 ↔ **−17 N·m ~ +17 N·m**），`bit7..0 = 电机 ID`
- 8 字节数据（**高字节在前，低字节在后 = 大端**，这是最容易踩的坑）：

| 字节 | 含义 | 范围 |
|---|---|---|
| Byte0–1 | 目标角度 | 0…65535 ↔ (−4π, 4π) |
| Byte2–3 | 目标角速度 | 0…65535 ↔ (−44, 44) rad/s |
| Byte4–5 | Kp | 0…65535 ↔ (0.0, 500.0) |
| Byte6–7 | Kd | 0…65535 ↔ (0.0, 5.0) |

**两个直接结论**：

1. 协议允许 **±17 N·m**，但手册第 2 页的**额定负载是 6 N·m**。控制器按 6 N·m 限幅是对的（保守）；
   若要用到 17 N·m，需要手册给出峰值/持续时间依据。
2. 运控模式带 Kp/Kd，**驱动器内部会再闭环一次**。这意味着我们的控制器与驱动器之间存在
   串联的两个环——**驱动器的 Kp/Kd 必须设为 0（纯力矩模式）或明确登记**，否则会与我们的
   PD 叠加，产生未建模的动态。

## 4. STM32H723VGT6 外设分配（建议）

| 外设 | 用途 | 说明 |
|---|---|---|
| FDCAN1 | 4 个灵足 01（髋/曲柄 ×2） | 1 Mbit/s 或更高，视驱动器支持 |
| FDCAN2 | 2 个 MF9025（轮） | 1 Mbit/s（协议默认） |
| TIM6 | 1 kHz 控制中断 | 驱动 `ml1_loop_1khz()` |
| IWDG | 独立看门狗 | **故障时不喂**（`main.c` 已如此实现） |
| USART1 | 调试/遥测 | 输出状态、故障码 |
| GPIO | 急停输入、LED 状态 | 急停必须**同时**能切断驱动器使能，不能只靠软件 |

H723VGT6 是 Cortex-M7 @ 550 MHz、带 FDCAN1/2/3 和 FPU，算力对 1 kHz 的 6 电机控制绰绰有余。

## 5. 一个必须解决的带宽问题

标准帧 8 字节 ≈ 111–135 bit（含填充）。1 Mbit/s 下单帧 ≈ **111–135 µs**。

| 拓扑 | 每周期帧数 | 总线占用 |
|---|---:|---:|
| 全部挂一条 1 Mbit/s | 6 | **67–81%**（偏高，不建议） |
| **分两条各 3 帧** | 3 + 3 | **33–40%**（推荐） |
| 单条 2 Mbit/s | 6 | 33–40%（若驱动器支持） |

结论：**至少分两条 CAN**，或把波特率提到 2 Mbit/s。1 kHz 下把所有 6 个电机塞进一条 1 Mbit/s
总线，占用会顶到 80%，没有余量给回复帧和重传。

## 7. 接线与供电（`wheel_jiexian.pdf`，MHF 驱动手册）

### 7.1 供电：两条电机线电压不重合

| 部件 | 电压范围 | 额定 |
|---|---|---|
| MHF/DHF 轮驱动器 | **7.4 – 32 V**（手册要求 DC24V 接线） | — |
| 灵足 RobStride 01 | **24 – 48 V** | 36 V |

**唯一重叠区间是 24–32 V。** 所以：

- 36 V 单轨**不行**——超过轮驱动器 32 V 上限；
- 建议 **24 V 或 28 V 单轨**，两者都能工作；代价是灵足 01 在 24 V 下达不到 36 V 时的转矩/转速；
- 若要各自发挥，就必须**两套电源**（轮 24 V、腿 36 V），并注意共地。

### 7.2 接口定义（ZH1.5-8PIN，DHF50/DHF70）

| 引脚 | 含义 |
|---|---|
| `B/L` | RS485-B **或 CAN-L** |
| `A/H` | RS485-A **或 CAN-H** |
| `V-` ×3 | 电源负极 |
| `V+` ×3 | 电源正极 |
| `T` / `R` | UART TX / RX（只用于上位机调参） |
| `G` | 信号地 |
| `5V` | 5 V 输出 |

相线走 GH1.25-4PIN（Phase A/B/C + 刹车），刹车另有两针（`BRAKE`、`BRAKE-RES`）。

### 7.3 终端电阻

- 手册要求**总线两端各接 120 Ω**；
- 轮驱动自带：**拨码第 4 位 ON 即接通 120 Ω**（ID 1–32 用前 3 位）；
- 因此一条总线上只需在**链路最远端**再补一个 120 Ω，不要两条都开。

### 7.4 轮驱动的电流刻度（可用来推力矩上限）

| 项 | 值 |
|---|---|
| 转矩电流读数 | **±2048 ↔ ±16.5 A**（约 8.06 mA/LSB） |
| `Max Torque Current` 限制参数 | 0 – 2000（比值），**这才是真正的力矩上限** |
| `Max Speed` | 0 – 72000 dps |
| `Protect Lost Input Time` | 信号丢失保护时间（ms）——**驱动器自带通信超时保护，务必开启** |
| CAN 波特率 | 125K / 250K / 500K / **1 Mbps（默认）** |
| 广播模式 | 4 台同时，需 ID 1–4，CAN 500K/1M，**仅支持扭矩模式** |

**注意**：型号 `MHF 70 25 - 28T 18bit` 里的 `70` 是外径、`25` 是定子铁芯高度、`28T` 是匝数，
**`25` 不是减速比**。减速比与 Kt 仍未确认，所以 N·m 还换算不出来——目前只能用
"电流 LSB" 做单位，或保守按静态需求反推。

### 7.5 两条总线为什么必须分开

| | RobStride 01 ×4 | MHF 轮 ×2 |
|---|---|---|
| 帧格式 | **29 位扩展帧** | **11 位标准帧** |
| 波特率 | 1 Mbps | 1 Mbps（默认） |
| ID 规则 | `bit28..24`类型 / `bit23..8`数据 / `bit7..0` 电机ID | `0x140 + 节点ID` |

两者帧格式不同、ID 语义不同，混在一条总线上既浪费仲裁优先级、又容易在调试时搞错。
配合前面 1 kHz 的带宽估算（6 帧占 67–81%），**FDCAN1 给 4 个灵足、FDCAN2 给 2 个轮** 是唯一合理分配。
